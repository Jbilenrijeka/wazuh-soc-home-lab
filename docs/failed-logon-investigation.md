# Windows Failed Logon Investigation

## Objective
Verify that a failed Windows logon is recorded locally, collected by the Wazuh agent, and detected in Wazuh.

## Scope
This was an authorized, controlled test on my own Windows endpoint using the dedicated local account `soc-test`.

## Environment
- Windows endpoint / Wazuh agent: ASUSwin11
- Agent ID: 001
- Wazuh manager: wazuhlab
- Log source: Windows Security event channel
- Test date: 6 November 2026
- Local timezone: Europe/Berlin (UTC+1)

## Test Procedure
1. Used "Run as different user" on cmd.exe.
2. Entered the local test account and deliberately supplied an incorrect password.
3. Observed the message: "The username or password is incorrect."
4. Queried Windows Security events using PowerShell.
5. Searched Wazuh Threat Hunting for Event ID 4625 and the test account.
6. Inspected the resulting alert details and captured screenshots.

## Evidence
Windows recorded two failed logons at 13:13:40 and 13:13:56 local time.
![PowerShell showing Windows Security Event ID 4625 for soc-test at 13:13:40](<Screenshot (690).png>)


Wazuh displayed two matching alerts at:
- 13:13:41.184
- 13:13:57.425

Both alerts used rule 60122:
"Logon Failure - Unknown user or bad password"

The inspected Wazuh document contained:

| Substatus | 0xc000006a | Incorrect password |
| Agent | ASUSwin11 / 001 | Endpoint reporting the event |
| Wazuh rule ID | 60122 | Failed authentication detection |
| Wazuh rule level | 5 | Alert severity |
| Windows event record ID | 4082558 | Identifier of the inspected Windows record |

## Timestamp Correlation
The inspected event had Windows system time:
2026-11-06T12:13:56.3804079Z

This corresponds to 13:13:56.3804079 in Berlin.
The Wazuh alert timestamp was 13:13:57.425 local time, approximately one second later.

## Assessment
The event fields match the deliberate local failed-logon test.
The substatus provides a more specific explanation than the general alert description: an incorrect password.

The alert included MITRE ATT&CK T1531 (Account Access Removal) as rule metadata. This event alone does not demonstrate that technique.

## Conclusion
The test validated Windows Security event collection and Wazuh detection for this failed-logon scenario.

These are real logs generated by a controlled laboratory test, not evidence of a confirmed malicious incident.

## Limitations
This test does not establish detection coverage for brute-force attacks, remote logons, or other attack scenarios.

Screenshots were captured during the test; adding them to this repository remains a documentation step.
